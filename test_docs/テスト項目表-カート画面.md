# テスト項目表-カート画面

## 対象

- カート画面の表示処理 `GET /cart`
- カート画面での数量更新処理 `POST /cart/items/{productId}/update`
- カート画面での削除処理 `POST /cart/items/{productId}/delete`
- カート画面表示に関わる Service / Repository の単体テスト

## 前提・補足

- 本項目表は、既存実装の `CartController`、`CartService`、`CartRepository`、`cart.html` を前提としている。
- カート内の商品一覧は `products` テーブルと `cart_item` テーブルを結合して取得し、同一商品の数量は集計される。
- 数量更新時は `CartService#updateCartItem()` で在庫チェック後に既存データを削除し、更新数量で再登録する。
- 削除時は `CartRepository#deleteCartItemsByProductId()` により該当商品を `cart_item` から削除する。
- カート画面のヘッダーでは `商品一覧` はリンク、`カート` は押下不可表示である。
- `買い物を続ける` は `GET /products`、`注文手続きへ` は `GET /orders/confirm` へ遷移する。

## 実行網羅の考え方

- C0 は、`GET /cart` の正常表示、`POST /cart/items/{productId}/update` の正常系、数量更新異常系、削除系を最低 1 回ずつ通す。
- C1 は、`CartController#showCart` の初期フォーム分岐、`CartController#updateCartItem` の `bindingResult.hasErrors()` の真偽、更新成功経路、例外経路、`deleteCartItem` の削除経路を通す。
- `CartService#updateCartItem()` は、在庫チェック成功時の delete → insert 経路と、在庫チェック失敗時に後続処理へ進まない経路の両方を確認する。
- `CartRepository#findCartItems()` は、JOIN による表示項目取得、`SUM(quantity)` による集計、空リスト返却の各経路を確認する。
