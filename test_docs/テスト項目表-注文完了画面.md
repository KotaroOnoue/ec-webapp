# テスト項目表-注文完了画面

## 対象

- 注文完了画面の表示処理 GET /orders/complete/{orderId}
- 注文完了画面表示用の注文番号取得に関わる Service / Repository の単体テスト

## 前提・補足

- 本項目表は、既存実装の OrderController、OrderService、OrderRepository、OrderCompleteModel、order-complete.html を前提としている。
- 注文完了画面では orders テーブルに保存済みの注文情報から order_id を取得し、画面に表示する。
- OrderController#showOrderComplete() は OrderService#getOrderComplete() の戻り値が null の場合、商品一覧画面へリダイレクトする。
- OrderService#getOrderComplete() は OrderRepository#findByOrderId() の結果をもとに OrderCompleteModel を生成し、現在の仕様では orderId のみを画面へ渡す。
- order_id は注文確定時に採番済みの値を利用するため、注文完了画面側では新規採番処理を行わない。
- 「商品一覧に戻る」ボタンは GET /products への画面遷移を意図したリンクである。

## 実行網羅の考え方

- C0 は、GET /orders/complete/{orderId} の正常表示、存在しない注文IDでのリダイレクト、Service の正常変換、Repository の正常取得を最低 1 回ずつ通す。
- C1 は、OrderController#showOrderComplete() の order が取得できる経路と null でリダイレクトする経路を両方通す。
- OrderService#getOrderComplete() は、Repository から OrderEntity が返る経路と null が返る経路を両方確認する。
- OrderRepository#findByOrderId() は、存在する order_id と存在しない order_id の両方を確認し、あわせて adress 列から address フィールドへのマッピングを検証する。

## 優先実装候補

- まず OCM-C-01、OCM-C-04、OCM-C-08、OCM-S-01、OCM-S-04、OCM-R-01、OCM-R-04 を優先すると、注文完了画面の主要表示と取得異常系を短時間で押さえやすい。
- 次に OCM-C-06、OCM-C-09、OCM-C-10、OCM-S-03、OCM-S-05、OCM-R-03、OCM-R-06 を追加すると、導線、境界値、分岐網羅、orders 定義準拠の確認を補強できる。
