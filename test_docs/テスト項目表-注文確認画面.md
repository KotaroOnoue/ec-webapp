# テスト項目表-注文確認画面

## 対象

- 注文確認画面の表示処理 GET /orders/confirm
- 注文確定処理 POST /orders
- 注文確認画面表示と注文保存に関わる Service / Repository の単体テスト

## 前提・補足

- 本項目表は、既存実装の OrderController、OrderService、OrderRepository、CartService、order-confirm.html を前提としている。
- 注文確認画面では CartService からカート内容と合計金額を取得し、OrderForm で配送先情報を受け取る。
- 注文確定時は OrderService#placeOrder() が orders テーブルへ保存し、cart_item を全削除した後、採番した order_id 付きで /orders/complete/{orderId} へリダイレクトする。
- ヘッダーでは 商品一覧 と カート はリンク、注文確認 は押下不可表示である。
- 郵便番号はハイフンなし 7 桁、電話番号は 10 桁または 11 桁の数字を前提とする。
- 空カートで注文確定した場合は IllegalArgumentException を通じて /orders/confirm にエラーメッセージ付きで戻る。

## 実行網羅の考え方

- C0 は、GET /orders/confirm の正常表示、POST /orders の正常系、入力バリデーション異常系、空カート異常系を最低 1 回ずつ通す。
- C1 は、OrderController#showOrderConfirm の初期フォーム分岐、OrderController#placeOrder の bindingResult.hasErrors() の真偽、正常リダイレクト経路、空カート例外経路を通す。
- OrderService#placeOrder() は、totalAmount <= 0 の分岐、正常保存分岐、deleteAllCartItems() 呼び出し分岐を両方確認する。
- OrderRepository は findNextOrderId の空テーブル時と既存データあり時、insertOrder の保存、findByOrderId の存在有無を確認する。
