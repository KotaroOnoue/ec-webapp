# テスト項目表-商品詳細画面

## 対象

- 商品詳細画面の表示処理 `GET /products/{productId}`
- 商品詳細画面からのカート追加処理 `POST /cart/items`
- 商品詳細表示とカート追加に関わる Service / Repository の単体テスト

## 前提・補足

- 本項目表は、既存実装の `ProductController`、`ProductService`、`ProductRepository`、`CartRepository`、`products-detail.html` を前提としている。
- 商品詳細画面では `ProductService#getProductById()` で商品情報を取得し、`ProductController#prepareProductDetailModel()` で `purchasable` と `maxSelectableQuantity` を設定している。
- 数量プルダウンの選択肢は `1` から `min(stock, 99)` までで、在庫切れまたは販売停止中のときは `select` と `submit` が無効化される。
- カート追加時の保存先は `cart_item` テーブルであり、数量は `1..99` の範囲である。
- 商品詳細画面からのカート追加は `redirectTo=/products/{productId}` を使って同一詳細画面へ戻る。
- 存在しない商品 ID や販売停止商品の扱いは、現行実装では `ProductUnavailableException` を通じてエラーメッセージ付きリダイレクトになる。

## 実行網羅の考え方

- C0 は、`GET /products/{productId}` の正常表示、`POST /cart/items` の正常追加、数量バリデーション異常、在庫超過異常を最低 1 回ずつ通す。
- C1 は、`ProductController#showProductDetail` の初期フォーム分岐、`ProductController#addToCart` の `bindingResult.hasErrors()` の真偽、`isProductDetailPath(redirectTo)` の真、正常追加経路、例外発生経路を通す。
- `ProductService#validateAddToCart` は、数量範囲チェック、販売状態チェック、在庫超過チェックの各分岐で真偽を両方通す。
- `prepareProductDetailModel()` は、`purchasable` が `true/false` になる条件と、`maxSelectableQuantity` が `stock` と `99` のどちらで決まるかを両方確認する。
