# テスト項目表-商品一覧画面

## 対象

- 商品一覧画面の表示処理 `GET /products`
- 商品一覧画面からのカート追加処理 `POST /cart/items`
- 商品一覧表示に関わる Service / Repository の単体テスト

## 前提・補足

- 本項目表は、既存実装の `ProductController`、`ProductService`、`ProductRepository`、`products.html` を前提としている。
- 販売中の商品だけを DB から取得する仕様は、Repository と Service の両レイヤで確認する。
- カート追加時の数量は画面上は固定で `1` だが、単体テストでは異常系確認のため `0`、`100`、`null` 相当も送信する。
- 仕様文には「在庫なしの場合に押せる」とあるが、現行実装の画面では `カートに追加` ボタンは在庫 0 のとき `disabled` になる。そのため、単体テスト項目は現行実装に合わせて「押下不可」としている。仕様を優先する場合は実装修正が必要。
- JUnit を用いた単体テストを前提とし、Controller は MockMvc、Service/Repository は Spring Boot Test + H2 を想定する。

## 実行網羅の考え方

- C0 は、少なくとも `GET /products` の正常表示、`POST /cart/items` の正常系、バリデーション異常系、在庫超過異常系で主要文を 1 回以上通す。
- C1 は、`ProductController#addToCart` の分岐として `bindingResult.hasErrors()` の真偽、`isProductDetailPath(redirectTo)` の偽、正常追加経路、例外発生経路を通す。
- `ProductService#validateAddToCart` は、数量範囲チェック、販売状態チェック、在庫超過チェックの各分岐で真偽を両方通す。
- `ProductRepository#findOnSaleProducts` は、SQL の抽出条件が `ON_SALE` のみに効いていることを確認する。

## 優先実装候補

- まず既存テストに近いものとして `PL-C-01`、`PL-C-04`、`PL-C-12`、`PL-C-14`、`PL-S-01`、`PL-S-07`、`PL-S-08`、`PL-R-01` を優先すると、正常系と重要異常系を短時間で固めやすい。
